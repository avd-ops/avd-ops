Power Platform and low-code governance method

methods/power-platform.md · Edition cfcc302 of avd-assess, 2026-10-27. What changed

How to judge the Power Platform control plane (power-platform) when makers, Power Automate Desktop flows, or line-of-business apps run on Azure Virtual Desktop session hosts or reach data inside the AVD virtual network ([G1]).

Method

  1. Ask whether the estate uses Power Platform in or alongside AVD (intake.powerPlatformPlaneScope: "used" or "not-used") before scoring Power Platform checks ([G2], [G1]).
  2. Inventory non-default Power Platform environments and Managed Environments from the Business Application Platform (BAP) read-only API so every sandbox and production environment used with AVD is visible ([1, environment-coverage], [G1]).
  3. Check Data Loss Prevention (DLP) policy coverage across every non-default environment: require at least one tenant-wide or environment-scoped DLP policy classifying connectors into Business, Non-Business, and Blocked groups ([1, connector-groups], [1, environment-coverage], [G1]).
  4. Check default connector group classification so uncategorized connectors land in Blocked or Confidential rather than unrestricted sharing ([1, default-group-blocked], [G1]).
  5. Check Power Platform VNet integration (Enterprise Policies) when Power Platform environments connect to private resources on the AVD spoke or hub virtual network, verifying Microsoft.PowerPlatform/enterprisePolicies and subnet delegation to Microsoft.PowerPlatform/enterprisePolicies ([2, enterprise-policy-subnet], [2, delegated-subnet-egress], [G1]).
  6. Check Power Automate Desktop machine-group governance when unattended or attended RPA flows run on AVD session hosts ([G1]).
  7. Score Power Platform checks as not applicable when intake.powerPlatformPlaneScope is "not-used" (the default for AVD estates that do not use Power Platform), so non-Power-Platform estates suffer no score or coverage penalty ([G1], [G3]).

Not yet known

  • Whether read-only BAP API calls with a service principal without Power Platform Administrator or System Administrator role return full DLP policy assignments in every sovereign and commercial cloud ([G1]).
