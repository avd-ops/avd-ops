Scoring method

methods/scoring.md · Edition cfcc302 of avd-assess, 2026-10-27. What changed

How check outcomes roll up, and which target-state decisions the evidence can support. No open standard exists, so this method is ours and labeled as a hypothesis ([G1]).

Method

  1. Score each Well-Architected pillar as the passing severity weight over the assessed weight, with a warn counting half, using the checklist's own severities as weights ([G1], [1]).
  2. Score each of the five control planes (azure, entra, intune, m365, power-platform) as a secondary rollup alongside the Well-Architected pillars using the same severity-weighted formula, and exclude not-applicable checks from both the score and coverage denominators ([G1]).
  3. Show coverage beside every pillar and plane score, the share of applicable checks that weren't unknown, so a score with little evidence can't pass for a good one ([G1]).
  4. Report decision readiness for each of the 10 target-state decisions: decidable, decidable with intake, or needs measurement ([G2]).
  5. Keep sizing decisions at "needs measurement" until measured use replaces the priors ([2, estimates-only], [G2]).
  6. Count sample check outcomes as performance-pillar checks, weighted like any other, with the sample check's coverage beside them ([G3], [G1]).
  7. Track change between runs rather than chasing a number ([3, milestones]).

Not yet known

  • Whether these scores track real problems. That takes runs, and each run that disagrees becomes an observation on [G1].
