Network method

methods/network.md · Edition a5a7eee of avd-assess, 2026-10-21. What changed

How to judge an estate's network, Azure side and client side, against what Microsoft publishes for AVD. It is the assessment method applied to the network, and it is a map: each step points at the pinned source, the fact that measures it and the check that judges it, and says so plainly where none exists. Nothing here restates Microsoft's lists; read them at the pin. avd-current-state implements it; findings go in the same report (contract C21). The rows are network.* in dimensions.yaml.

How RDP itself behaves on the network (reverse connect, Shortpath, STUN and TURN, multipath, QoS) belongs to the remote protocol pillar; this method judges whether the network lets it happen.

Azure side

  1. Topology first. Standalone spoke, peered to a hub, or on a Virtual WAN hub, and whether hosts need anything on-premises ([1, hub-shared-services], [2, managed-transit], [3, F01.01], [3, F01.02], [3, F01.03]). Entra-joined hosts need no private path for identity ([4, entra-joined-no-private]). Rows network.mode, network.hybrid.
  2. Address space with headroom for hosts and private endpoints; no source gives a sizing rule, so report free addresses against the plan ([5, address-headroom], [G1]). Row network.addressing.
  3. Every private name resolves privately from the hosts: a linked zone or forwarding for Files, Key Vault and AVD, and a resolver where on-premises must resolve them ([6, zone-per-service], [7, hybrid-resolution], [8, dns-zones]). Row network.dns.
  4. An explicit outbound method on every host subnet ([9, explicit-outbound], [9, private-subnets-default], [10, subnet-egress], [3, F01.04]). Row network.egress.
  5. The required endpoints reachable from a host, by service and FQDN tags, and nothing aimed at the platform addresses ([11, host-list], [11, service-and-fqdn-tags], [12, no-deny-no-route], [13, fqdn-tag-rules], [3, F01.05], [3, F01.07]). Only a read on a host proves reachability; a probe from anywhere else is unknown ([14, run-on-host], [O1]). Row network.required-endpoints.
  6. What may be inspected or tunneled. Forced tunneling is supported when the requirements hold ([4, forced-tunnel-supported]); no SSL termination or authenticating proxy for AVD ([15, no-ssl-termination], [15, no-auth-proxy], [3, F01.08]); the platform addresses are never proxied or tunneled ([12, never-proxy-or-tunnel]); a firewall default route needs the AVD service tag routed around it ([13, bypass-route-for-scale-in], [O2]). Firewall rules are intake. Row network.inspection.
  7. AVD Private Link, Azure side. Which of the four layouts, chosen on purpose, with the public access settings that match ([5, three-sub-resources], [5, four-scenarios], [5, public-access-settings]); the global endpoint on its own workspace and zone ([5, global-workspace], [5, separate-global-zone]); the provider re-registered ([8, re-register-provider]); the connection endpoint's full TCP range open wherever ports to it are restricted ([5, full-port-range], [O3]); UDP only with the opt-in ([5, udp-opt-in]); agents restarted after a change ([5, agent-restart]). Profile storage and Key Vault behind private endpoints ([3, F01.10]). Row network.private-access.
  8. Operators come in another way: Bastion or a jumpbox, never a public RDP port ([16, admin-path], [G1]). Row network.admin-access.
  9. Watch it: flow logs with traffic analytics, and path tests where hosts depend on a hub or on-premises ([17, flow-logging], [18, path-tests], [4, nsg-on-all-subnets]). Row network.monitoring.
  10. Recovery region: the same network capabilities, or at least identity and DNS ([4, dr-network]); the recovery model itself is in reliability.dr-model.

Client side

  1. Every user network allows the client endpoint list and reaches the region within the round-trip target, measured from that network ([11, client-list], [19, rtt-under-150], [O4]). Row network.client.
  2. Proxies on the user network are bypassed for AVD or sit in the same geography; client proxy support differs by platform ([15, bypass-proxies], [15, same-geography], [15, client-proxy-support]).
  3. AVD Private Link, client side. Where users connect privately, each user network resolves the discovery, feed and gateway names to the endpoints over VPN or ExpressRoute; discovery stays public by design; no mixed public and private feeds on a network without internet; clients at the supported versions ([5, client-dns-sequence], [5, global-workspace], [5, mixed-feed-limit], [8, client-versions], [7, hybrid-resolution], [G2]). Row network.client-private-link.
  4. Bandwidth per user and in total, estimated first and then measured ([20, per-scenario-estimates], [3, F01.09]). Row network.bandwidth.
  5. Device VPN and security agents (SSE, ZTNA, VPN client categories, web proxies, TLS inspection): RDP split out of every tunnel and left uninspected, sign-in traffic excepted ([21, bypass-tunnels], [21, no-tls-inspection], [21, auth-inspection-ok]); a path that can't carry UDP leaves RDP on TCP ([15, proxy-forces-tcp]). Intake intake.clientAgents and intake.agentRdpBypass; categories only ([G3]). Row network.client-agents.
  6. Prove it with users: a proof of concept from the real networks before the move ([3, C02.04]).

Client-side steps are intake or a reviewer's test on the user's network ([G2]); nothing reads them automatically.

Extension points

  • AVD on Azure Local (network.azure-local): a host pool is all Azure or all Azure Local ([22, no-mixed-pools]); no method yet.

Where the network lives in the family

The slices are the same as for security: avd-assess holds the map and this method, avd-current-state collects the facts and runs the checks from a pinned copy, avd-landing-zone builds a design that should pass them, and the layers above explain and change it. The table, the draft checks and what each needs are in [G1].

Not yet known

  • The draft checks in [G1] need facts avd-current-state doesn't collect yet; each enters method.json with its facts.
  • No host-side read exists for required endpoints, private name resolution or proxy and inspection on a host.
  • Whether the landing zone's private endpoint NSG and its hub route without an AVD bypass matter in practice ([O3], [O2]).

Our observations

What our own runs showed about a cited claim. Evidence links are public and pinned.

  1. [O1]extends endpoint-probe-off-host, on avd-url-check-tool#run-on-host, 2026-10-21. avd-current-state's validator probes a fixed list of AVD endpoints from wherever it runs, usually Cloud Shell, and says so; that proves nothing about the session host subnet. Its list also predates the current required list (newer service domains, the relay UDP range, certificate endpoints on TCP 80, the platform addresses). An authoritative result needs the Agent URL Tool's output from a host, and a probe off the host should count as unknown, not pass.
  2. [O2]not yet tested hub-route-without-avd-bypass, on firewall-avd#bypass-route-for-scale-in, 2026-10-21. In hub-peered mode the landing zone routes 0.0.0.0/0 from the host subnet to the hub firewall and adds no route for the WindowsVirtualDesktop service tag to the internet, the bypass the source gives against disconnections during firewall scale-in. With AVD Private Link on, the session host's gateway connection goes through the private endpoint, which may cover the main path; other service traffic still crosses the firewall. Not yet run against a hub firewall.
  3. [O3]not yet tested private-endpoint-nsg-narrower-than-avd-needs, on avd-private-link#full-port-range, 2026-10-21. The landing zone enforces an NSG on its private endpoint subnet that allows TCP 445 from the hosts and TCP 443 from the network and denies the rest, while the source says the connection endpoint needs TCP 1-65535 whenever ports to it are restricted. Recorded sandbox runs connected sessions through landing zones built this way (to confirm from their run records), so either the session host side only needs 443 or the gap shows up under conditions not yet run (private client connections, other gateways). To test in a run that already deploys the landing zone, then record agrees or disagrees.
  4. [O4]extends region-latency-from-the-user, on avd-prerequisites#rtt-under-150, 2026-10-20. Latency measured from Cloud Shell says nothing about users, because Cloud Shell runs in an Azure datacenter. Measure round-trip time from the user's device, against endpoints verified to be regional.
