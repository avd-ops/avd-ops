FinOps method

methods/finops.md · Edition a5a7eee of avd-assess, 2026-10-21. What changed

How to judge what an estate costs, and whether it costs what it should, against what Microsoft and the FinOps Foundation publish. It is the assessment method applied to the cost pillar, with the extra sources cost needs. avd-current-state implements it; the findings go in the same report (contract C21). Nothing here is a bill, a quote or financial advice.

Method

  1. Scope to the workload: the FinOps capabilities one estate can show, workload and rate optimization, licensing, allocation, budgeting and unit economics, not the maturity of an organization's FinOps practice ([1, capabilities], [G1]).
  2. Start from Microsoft's lists: the review checklist's cost items ([2, E01.05], [2, E01.06], [2, E01.07] and the rest), the Well-Architected cost checklist ([3, CO:02]), and the AVD cost page ([4, two-sources]), read in the framework's order of inform, optimize, operate ([1, lifecycle]).
  3. Settle licensing first, because it decides whether per-user access pricing applies and it comes from the operator, not telemetry ([5, eligible-license-per-user], [5, per-user-access-external-only], [G1]).
  4. Judge hours before rates: a scaling plan on every pooled host pool ([2, E01.04], [6, scales-to-save-cost], [O1]), Start VM on Connect where hosts can be off ([7, power-on-when-needed]), and something that deallocates personal hosts, since nothing does by default ([8, no-automatic-deallocation]).
  5. Judge size and density with the sizing method's numbers, not against cost alone, and leave profile size and redirections unknown until a host-side read ([9, multisession-users-per-vcpu], [3, CO:14], [2, H04.03], [2, H04.07]).
  6. Read Advisor's cost results for the estate's resources and cite them rather than recompute them; a right-size note on an autoscaled host is a trade-off to review ([10, right-size-or-shutdown-vms], [10, unattached-disks], [G1]).
  7. Judge rates last: commit only the floor of hours that always run, after the hours and sizes are settled ([11, right-size-first], [G2]).
  8. Check allocation and guardrails: host pools and their hosts carry a cost allocation tag ([12, tag-host-pools-first], [12, cm-resource-parent]), and a budget that acts, not only alerts ([13, alerts-dont-stop], [O2]).
  9. Price with retail prices matched on product, SKU and meter, report an unmatched line instead of guessing, and call the result an upper bound ([14, unauthenticated-retail], [O3], [O4]).
  10. Report actual cost only once it has settled, with the time it was read; before that it is pending ([15, data-latency], [15, open-month-estimated], [O5]).
  11. Treat a deliberate trade-off as warn with its reason, such as a host kept on for a night batch, and a setting nobody chose as gap; a model never decides which ([G3]).
  12. Repeat on a cadence and compare with the last run, as for every other pillar ([16, milestones], [1, maturity-per-capability]).

Where FinOps lives in the family

FinOps isn't a separate project. Each foundation repo holds its usual slice, and the upper layers build on them; dependencies point down only, and avd-landing-zone and avd-current-state keep working with nothing above them.

  • avd-assess (this page): what it should cost, and why.
  • avd-current-state: what it costs now. It collects the cost facts and runs these checks from a pinned copy of this method.
  • avd-landing-zone: how it's built. It prices every deployment before it runs, its defaults should pass these checks, and it records each run's expected and actual cost.
  • avd-second-brain: why it costs what it does over the estate's life, including accepted spend.
  • avd-swarm: how it's operated, with its spend guard for lab runs and any change a plan a person approves.

The table and the reasons are in [G1]. The FinOps Foundation's own framework and the open-source FinOps toolkit cover the organization-wide practice; this method links to them rather than restating them ([17, tools], [18, common-billing-format]).

Not yet known

  • Most cost items need facts avd-current-state doesn't collect yet: scaling plans, tags, budgets and Advisor results ([G1]).
  • No run has measured how long a pay-as-you-go sandbox's actual cost takes to appear, or compared a month of running hours with the scaling plan ([O5], [O1]).
  • There is no published or measured target for cost per user, so it is reported without a score.

Our observations

What our own runs showed about a cited claim. Evidence links are public and pinned.

  1. [O1]not yet tested scaling-and-start-on-connect-by-default, on avd-autoscale#scales-to-save-cost, 2026-10-20. The landing zone deploys a power management scaling plan (depth-first ramp-down that stops hosts at zero sessions, without forcing sign-out) and Start VM on Connect on by default, and every resource group and resource carries workload and environment tags. No run has yet compared a month of running hours with the schedule, so the saving is Microsoft's claim, not our evidence. The landing zone doesn't set the cm-resource-parent tag.
  2. [O2]extends budget-alert-needs-a-lock, on cost-management-budgets#alerts-dont-stop, 2026-10-20. Budgets only alert, so the landing zone wires its budget to an action group that runs a Lock runbook, and avd-swarm's spend guard enforces caps before a lab run opens instead of relying on the budget. For AVD a plain deallocate isn't enough either, because Start VM on Connect and the scaling plan start the hosts again at the next sign-in or ramp-up; Lock drains, sets the scaling plan exclusion tag and turns Start VM on Connect off. The budget-to-runbook path hasn't run against a real deployment yet.
  3. [O3]extends retail-price-lookalike-meters, on retail-prices-api#unauthenticated-retail, 2026-10-20. A real preflight run priced session hosts and OS disks as unmatched because the API returned lookalike meters with the same SKU and meter name, a CloudServices product at the Windows rate beside Virtual Machines at the base rate, and a Premium Page Blob meter beside Premium SSD Managed Disks. Private Link and NAT Gateway are listed only under the Global region. A price is matched on product, SKU and meter, and a line that matches none or several is reported with what it saw rather than guessed.
  4. [O4]agrees estimate-before-deploy, on waf-cost-optimization-checklist#CO:02, 2026-10-20. The landing zone prices the compiled plan from retail prices before anything is deployed, with run hours from the power settings and an upper bound where the schedule rather than use decides (168 hours a week without a scheduled stop). Lab runs in the family don't start without that written estimate, a cap and teardown evidence, and avd-swarm's spend guard refuses a run whose estimate has an unpriced line or passes a cap. Retail prices are list prices, so the estimate is an upper bound for anyone with negotiated rates or commitments.
  5. [O5]not yet tested run-cost-settles-late, on cost-management-data#data-latency, 2026-10-20. The run recorder spec keeps each run's expected and actual cost as contract C17 (avd-run-cost/v1), appends a reading until it is unchanged for 72 hours, and reports pending rather than a guess until then. For scale, an earlier one-host sandbox demo cost 0.97 USD for about eight hours. How long the actual took to appear in a pay-as-you-go sandbox hasn't been measured yet (the spec's open question U5).
