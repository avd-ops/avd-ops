Troubleshooting and diagnostics method

methods/diagnostics.md · Edition b0875cd of avd-assess, 2026-10-28. What changed

How to find out why something is wrong in an AVD estate: which source answers which symptom, in what order to read them, and what stays unknown. It is the assessment method applied to the troubleshooting and diagnostics pillar (diagnostics in dimensions.yaml). It is the one pillar that is a flow rather than a list of settings, so it needs this page. Microsoft documents each component's troubleshooting; the method links to those pages and adds only the map that joins them: the data sources ([G1]), the error-code map ([G2]) and one triage flow per symptom. The monitoring pillar says the data must exist; this page says how to read it when something is wrong.

Method

  1. Start from the symptom the operator reports (intake.reportedSymptoms), and say whether it is one user, one host pool or everyone. With no symptom, read the facts in steps 3 and 4 and treat anything unusual as the symptom ([G1]).
  2. Rule out the platform first: Service Health for an AVD incident or advisory ([1, service-health-first], [2, service-issue-and-advisory]).
  3. Read host health from the API, which needs only Reader: status, failing checks, stale heartbeats, update state ([3, health-check-results], [4, status-load-balancing]).
  4. Read the service's own record if diagnostics are on: connection outcomes, errors by code and ServiceError, checkpoints ([5, categories], [5, connection-states], [5, service-error-split]). Absent diagnostics, the triage is blind on the service side; say so and hand the gap to the monitoring pillar.
  5. Follow the flow for the symptom: [G3], [G4], [G5], [G6], [G7]. Each names the sources in the order to read them and the pillar that owns the fix.
  6. Look every code up in the map, never by guess; an unmapped code stays unmapped ([G2], [6, errors-not-all-documented]).
  7. Go to the host, the directory or the client only when the flow says so, and record which read it needed: host event and FSLogix logs, Entra sign-in logs, client logs ([7, app-event-sources], [8, profile-log-first], [9, sign-in-logs-first], [10, per-platform]).
  8. Escalate what is the platform's: ServiceError true and anything past the component pages go to Microsoft with the correlation ID ([5, service-error-split], [1, escalation-tracks]).
  9. Record the finding as a fix in its owning pillar, not here: this pillar finds causes; the remediation method plans the change ([G8]).
  10. Record what stays unknown and why: no diagnostics, a connection that never reached the service, recent rows not yet ingested, or a read nobody could make ([5, unreached-not-logged], [6, ingestion-delay]).

Not yet known

  • Whether the flows find a fault planted on purpose. One sandbox run (a blocked required URL, a stopped agent, a full profile share) checks that the facts and the flows catch each; it is planned with the scaling batch and waits on a cost estimate and the owner's go.
  • What error counts, failure shares and connection times are normal. No source publishes one ([G1]); the estate's own last run is the comparison until evidence submissions give more ([G9]).
  • No check runs yet. The log facts need a Log Analytics read in the collector; the health check fact needs one more field from a read it already makes.

Our own method (gaps)

Where no published source covers a step, avd-assess writes the method and says what was searched and not found.

  1. [G1]diagnostics-scope: what a troubleshooting and diagnostics assessment can read, and which part becomes a fact.
  2. [G2]error-code-map: one map from the code an operator sees to its meaning and its flow.
  3. [G3]triage-cannot-connect: triage when a user can't sign in, sees no resources or can't connect.
  4. [G4]triage-host-unhealthy: triage when a session host is unhealthy.
  5. [G5]triage-slow-logon: triage when sign-in to a session is slow.
  6. [G6]triage-slow-session: triage when a session is slow or disconnects.
  7. [G7]triage-profile-failed: triage when a user profile fails to load.
  8. [G8]remediation-plan: the remediation plan.
  9. [G9]evidence-intake: one evidence intake for everyone.
