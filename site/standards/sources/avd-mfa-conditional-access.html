Enforce Microsoft Entra multifactor authentication for Azure Virtual Desktop using Conditional Access

references/avd-mfa-conditional-access.yaml · Edition a5a7eee of avd-assess, 2026-10-21. What changed

Microsoft Learn content (link only). We keep one line in our own words per claim and link the source; its text stays with its publisher. The page the review checklist's G04.01 links to. #licensing published

Conditional Access needs Entra ID P1 or P2 for the users and can't be used while Security Defaults are on.

Target the Azure Virtual Desktop app for the service and gateway, and the Windows Cloud Login app for session host sign-in when single sign-on is on.

#per-user-mfa-off published

Legacy per-user MFA alongside Conditional Access breaks sign-in to Entra joined hosts; turn it off and use Conditional Access only.

✓ mapped○ measurable○ validated

Not cited by a method yet. Cite: avd-assess@a5a7eee:references/avd-mfa-conditional-access.yaml#per-user-mfa-off

#sign-in-frequency published

Sign-in frequency decides how often users reauthenticate; "every time" works only on the Windows Cloud Login app with single sign-on, and a running connection isn't interrupted.

✓ mapped○ measurable○ validated

Not cited by a method yet. Cite: avd-assess@a5a7eee:references/avd-mfa-conditional-access.yaml#sign-in-frequency

#all-apps-conflicts published

Policies on all cloud apps also hit AVD; check them for device compliance (which Entra joined hosts may not meet), location rules (the IP differs between the two apps) and blocks on the Windows 365 app that Windows App also signs in to.
