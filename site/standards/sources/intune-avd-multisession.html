Using Azure Virtual Desktop multi-session with Microsoft Intune

references/intune-avd-multisession.yaml · Edition cfcc302 of avd-assess, 2026-10-27. What changed

Microsoft Learn. Using Azure Virtual Desktop multi-session with Microsoft Intune. Pinned at git_commit_id a5e9242, updated 2026-10-12; read 2026-10-21. Microsoft Learn content (link only). We keep one line in our own words per claim and link the source; its text stays with its publisher. The one Microsoft page that says what Intune can and can't do on Windows Enterprise multi-session hosts. Most of this pillar's limits come from it.

Read the source

The Learn pin names the version we read; Microsoft does not publish that commit, so the pin is a record, not a readable copy. The live page may have changed since the read date.

Claims (21)

#device-and-user-scope published

Intune manages multi-session hosts with device-scope configuration assigned to device groups and user-scope configuration assigned to user groups; a device setting assigned to users, or the reverse, reports Error or Not applicable.

✓ mapped○ measurable○ validated

Cited by Intune and host management method. Cite: avd-assess@cfcc302:references/intune-avd-multisession.yaml#device-and-user-scope

#enrollment-prerequisites published

Supported hosts are in a host pool deployed through Azure Resource Manager, in the same tenant as Intune, run AVD agent 1.0.2944.1400 or later, and are Entra joined with Intune enrollment turned on, or hybrid joined and enrolled with device credentials through Group Policy or co-management.

✓ mapped✓ measurable○ validated

Cited by Intune and host management method. Checks: asm-intune-hosts-managed. Cite: avd-assess@cfcc302:references/intune-avd-multisession.yaml#enrollment-prerequisites

#device-credentials published

Hybrid joined multi-session hosts must enroll with device credentials; enrollment with user credentials isn't supported and settings catalog policies fail on such hosts.

✓ mapped○ measurable○ validated

Cited by Intune and host management method. Cite: avd-assess@cfcc302:references/intune-avd-multisession.yaml#device-credentials

#one-mdm-provider published

Enrollment fails when the tenant has more than one MDM provider, or when the VM isn't part of a host pool created through Azure Resource Manager.

✓ mapped○ measurable○ validated

Cited by Intune and host management method. Cite: avd-assess@cfcc302:references/intune-avd-multisession.yaml#one-mdm-provider

#no-entra-ds published

Session hosts joined to Microsoft Entra Domain Services can't be managed with Intune.

✓ mapped○ measurable○ validated

Cited by Intune and host management method. Cite: avd-assess@cfcc302:references/intune-avd-multisession.yaml#no-entra-ds

#no-cloned-enrolled-image published

Intune doesn't support a cloned image of a machine that is already enrolled; replicated enrollment or identity tokens cause enrollment and sync failures, so images are captured before enrollment.

✓ mapped○ measurable○ validated

Cited by Intune and host management method. Cite: avd-assess@cfcc302:references/intune-avd-multisession.yaml#no-cloned-enrolled-image

#no-token-roaming published

Intune doesn't support token roaming between devices; with FSLogix or similar profile tools, identity tokens must not roam (FSLogix RoamIdentity off).

✓ mapped○ measurable○ validated

Cited by Intune and host management method. Cite: avd-assess@cfcc302:references/intune-avd-multisession.yaml#no-token-roaming

#apps-system-required published

Apps on multi-session must install in system context, be targeted to devices, and use Required or Uninstall intent; Available isn't supported, and a system app that depends on or supersedes a user-context app won't install.
