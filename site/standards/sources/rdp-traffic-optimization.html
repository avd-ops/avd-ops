Optimization of RDP traffic (Windows 365 and Azure Virtual Desktop)

references/rdp-traffic-optimization.yaml · Edition a5a7eee of avd-assess, 2026-10-21. What changed

Microsoft Learn. Optimization of RDP traffic (Windows 365 and Azure Virtual Desktop). Pinned at git_commit_id b0c12cb, updated 2026-10-07; read 2026-10-21. Microsoft Learn content (link only). We keep one line in our own words per claim and link the source; its text stays with its publisher. Filed under Windows 365, but the page says the gateway and TURN ranges it lists are dedicated to Windows 365 and Azure Virtual Desktop, and it names AVD deployments directly. It is the one Microsoft page that treats VPN, secure web gateway and SSE agents as a category. The address table itself stays on the page and in ref:avd-required-fqdn.

The Learn pin names the version we read; Microsoft does not publish that commit, so the pin is a record, not a readable copy. The live page may have changed since the read date.

#bypass-tunnels published

Send RDP traffic to the gateway and TURN ranges directly, outside VPN, secure web gateway and proxy tunnels, on both the user's device and the host; other traffic can keep using the tunnel.

#no-tls-inspection published

TLS inspection of RDP traffic isn't supported; RDP already nests one encrypted session inside another, so inspection adds jitter, latency and load and reduces throughput with no security benefit.

✓ mapped○ measurable○ validated

Cited by Network method. Cite: avd-assess@a5a7eee:references/rdp-traffic-optimization.yaml#no-tls-inspection

#local-egress published

Let RDP leave the user's network as close to the user as possible; backhauling it through a tunnel picks gateways and relays near the tunnel's exit instead of near the user.

✓ mapped○ measurable○ validated
