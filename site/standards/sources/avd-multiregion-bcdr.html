#active-active-vs-passive guidance

Each pooled host pool takes an active-active model (a second pool in another region serving users, near-zero RTO, no failover step) or active-passive (a standby pool users are moved to by reassigning application groups).

Don't use Site Recovery test failover for session hosts, because the duplicate VM registers with the control plane and conflicts with the original; start secondary hosts on a schedule and run the failover procedure with a test group instead.
