avd-azure

The Azure ARM and Bicep infrastructure control plane for Azure Virtual Desktop, orchestrated by avd-landing-zone.

More

The Azure Bicep deployment engine for cloud-native AVD estates: virtual networks, Private Link, Premium Azure Files for FSLogix, Key Vault, host pools, workspaces and session hosts (decision 0009).

The repo is the source of truth: avd-ops/avd-azure. This page says where it fits.

What it does

It deploys the Azure and AVD resource layer from Bicep with Private Link and Entra Kerberos.

  • Deploys multiple workspaces, Desktop and RemoteApp application groups, and Pooled or Personal host pools from Bicep.
  • Configures full AVD Private Link (connection, feed and global) and Private Endpoints for Azure Files and Key Vault.
  • Configures FSLogix on Premium Azure Files with Entra Kerberos and no storage keys, plus Azure Policy, Defender for Cloud and budget automation.
  • Joins session hosts to Entra ID with the Entra join extension (AADLoginForWindows) and enrolls them in Intune, where the avd-intune profiles apply.

How it fits

It is the Azure infrastructure stage orchestrated by avd-landing-zone and checked by avd-current-state.

  • Invoked at a pinned commit by avd-landing-zone or run directly from Azure Cloud Shell.
  • Consumes networking-outputs.json (C31) from avd-networking when running in HubPeered mode with a managed hub.
  • Binds application groups and RBAC to the user and admin groups from avd-entra, passed in as group IDs. Its handoff to avd-power-platform and avd-current-state is azure-outputs.json (--output-manifest / AVD_AZURE_OUTPUTS_PATH), defined by its avd-ops-azure-outputs/v1 contract schema.
