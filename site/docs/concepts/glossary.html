Shared contracts (C1–C25)

Versioned JSON contracts passed between repositories instead of shared code.

More
Term What it is Owner
Contract registry (C1–C25) The catalog of versioned JSON schemas and examples that connect the family repos without runtime code coupling avd-second-brain contracts
C6 (avd-knowledge-rule/v1) Machine-readable sizing, threshold, and architecture rules harvested into the knowledge base avd-second-brain contracts
C9 (avd-playbook-proposal/v1) A surface-aware remediation or operational plan proposed by the brain for human approval in avd-swarm, carrying a dataLossGuard block avd-second-brain decision 0027
C10 (avd-playbook-outcome/v1) The redacted execution and verification outcome returned to the brain after avd-swarm runs or rejects an approved plan avd-second-brain contracts
C11 (avd-current-state-facts/v1) A single-tenant, pseudonymized snapshot of counts, booleans, and public Azure values across all five control planes, with zero names or IDs avd-current-state README
C12 (avd-forensic-facts/v1) Pseudonymized user-experience and sizing aggregates (logon duration, concurrency, CPU/RAM demand) from the optional forensic tier avd-swarm spec §6d
C13 (avd-doc-findings/v1) Machine-readable documentation drift findings produced by the brain's sweep for the Scribe role to draft as PRs avd-second-brain docs-spec
C14 (avd-target-state/v1) An approved target-state architecture manifest consumed by avd-landing-zone's ConvertFrom-AvdTargetState.ps1 avd-assess contracts
C15 (avd-fact-register/v1) The canonical dictionary of every c11.*, c12.*, c19.*, and c25.* fact ID, its type, plane, and privacy classification avd-assess contracts/fact-register.json
C18 (avd-environment-record/v1) The lifecycle decision and event log for an environment, linking every change (why) to an accepted or drafted decision avd-swarm decision 0007
C19 (avd-intake/v1) Operator-answered business, residency, identity, and scope inputs that telemetry cannot observe avd-assess contracts
C21 (avd-assessment/v1) A scored, evidence-backed assessment report across the five control planes and eight architecture pillars avd-assess contracts
C23 (avd-assessment-review/v1) The operator's recorded disposition (fix, accept, defer) and rationale for each assessment finding avd-current-state portal
C24 (avd-remediation-plan/v1) An ordered remediation plan generated from an assessment report (C21), its review (C23), and the pinned method catalog avd-assess remediation method
C25 (avd-benchmark-result/v1) Pseudonymous Tier 1 (active synthetic) and Tier 2 (passive Log Analytics / Graph) performance benchmark percentiles (p50, p90, p95, p99) avd-assess benchmark contract

Architecture, maturity, and governance terms

The operating model, maturity levels, and safety boundaries shared by all repositories.

More
Term What it is Owner
Five control planes The split of desktop estates into Entra ID (avd-entra), Intune (avd-intune), Microsoft 365 (avd-m365), Azure ARM (avd-azure), and Power Platform (avd-power-platform), orchestrated by avd-landing-zone decision 0009
Desktop DevOps Unified declarative engineering, assessment, and approval-gated operations across AVD Pooled, AVD Personal, Windows 365 Cloud PCs, and Microsoft Intune decision 0012
Maturity (proven, pre-beta, design) How far a repo has been validated: proven (repeated real Azure runs and guards), pre-beta (built and tested offline, fewer live runs), or design (spec and spikes only) roadmap spec §6
Standing (run, guarded, built, designed) How strong the evidence is for a single security or architecture claim in avd-assess's security review map security review page
Governance gate & approve environment avd-swarm's check that validates evidence provenance, re-reads live state, verifies the approved plan hash, and requires a human approval before any write token is issued avd-swarm governance
Kill switch (run, halt-actions, halt-agents, halt-all) The layered tag and Conditional Access switch in avd-swarm that halts writes, model calls, or all automation immediately and can only be reset by the owner avd-swarm decision 0002
Run record (run-record/v1) The local evidence bundle (run-record.json, run-journal.jsonl, run-cost.json) written by avd-landing-zone during a recorded deployment or sandbox batch avd-landing-zone sandbox runs
Sandbox batch (go batch <id> $<total>) A priced queue of sandbox-run/v1 test items that refuses to spend a cent without the owner's exact approval phrase bound to the batch hash sandbox batches
Never delete the last copy The family rule that no script, teardown, or agent deletes profiles, backups, or run evidence without a verified copy elsewhere or explicit -DiscardLastCopy never delete the last copy
Never leave the meter running The family rule that anything billing by time is torn down, stopped, or scheduled off at the end of a run unless opted in with an explicit expiry never leave the meter running
Private companion repo (AVD_PRIVATE_REPO) The operator's own private Git repository where unredacted run records, cost ledgers, and customer estate vaults are stored, never in public repos private companion repo
