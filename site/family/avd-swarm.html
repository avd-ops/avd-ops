On top: how we automate it

avd-swarm

Agents that manage Azure and Entra ID without the portals. They read freely and change nothing until a person approves the exact plan.

Design and spike

What it does

  • A coordinator hands questions to specialist agents: readiness, deploy, hosts, images, users and cost.
  • Writes go through plans approved in GitHub Environments, with one layered kill switch only the owner resets.
  • The write path never runs in the public repo. Adopters run it from a private repo synced from a release tag.
  • Today only the S1a spike runs. Everything after the first two write actions is designed, not scheduled.

Try it in a lab

The S1a spike runs from the public repo alone. It prices itself first and refuses to deploy anything if the estimate is over the run cap ($20 by default) or would take the month past the monthly cap you give it, then deploys, asks its questions, tears down, checks nothing is left and records the run.

# Azure Cloud Shell (PowerShell), in a lab tenant and a sandbox subscription
if (-not (Test-Path ~/avd-swarm)) { git clone https://github.com/nickprignano/avd-swarm.git ~/avd-swarm }
Set-Location ~/avd-swarm; git checkout -q main; git pull -q --ff-only
./spikes/s1a/Invoke-Spike.ps1

It needs Claude quota in Microsoft Foundry (East US 2). Without it, add -Provider Anthropic to run the same questions on Anthropic's API, with no API key.

Full prerequisites and steps are in the README.
