avd-landing-zone

An Azure Virtual Desktop landing zone for cloud-native organizations: Entra ID-joined, Intune-managed, private by default, deployed end to end from one Bicep template.

Built

What it does

  • One opinionated path: no domain controllers, no line of sight to on-premises, no post-deployment scripts.
  • FSLogix on Premium Azure Files with Entra Kerberos and no storage keys; session hosts on Trusted Launch with encryption at host.
  • No default outbound access, AVD Private Link, Azure Policy, Defender for Cloud and a budget that switches hosts off when it runs out.
  • Strict Bicep linting, PSScriptAnalyzer, PSRule for Azure and what-if on every pull request; deploys through an environment-gated workflow.
  • A deployment portal in the browser that sizes the host pool and walks you through Cloud Shell, one pasted output at a time.

Try it in a lab

# Azure Cloud Shell (PowerShell)
if (-not (Test-Path ~/avd-landing-zone)) { git clone https://github.com/avd-ops/avd-landing-zone.git ~/avd-landing-zone }
Set-Location ~/avd-landing-zone; git checkout -q master; git pull -q --ff-only
./scripts/ops/Connect-AvdLandingZone.ps1
./scripts/ops/Test-AvdLandingZoneReadiness.ps1 -PreDeployment -ParameterFile parameters/dev.bicepparam -Location northcentralus -UsersGroup 'AVD Users' -AdminsGroup 'AVD Admins'
bash ./scripts/deploy/deploy.sh -p parameters/dev.bicepparam -l northcentralus --users-group 'AVD Users' --admins-group 'AVD Admins' --what-if

Full prerequisites and steps are in the README.
