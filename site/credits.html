Where it started

I started avd-ops in June 2026 as one Azure Virtual Desktop landing zone, built on my own time to see how far a cloud-native deployment could go as code. Every real run that broke something became a lesson and a guard, and those lessons grew into the other repos: an inventory, an assessment method, agents a person approves, and a memory of what each deployment taught. It's still a personal research project: only avd-landing-zone is proven on real deployments, and the rest is being built in the open. None of it is a solo act: it's 100% pair programmed with my buddy Claude.

What we send upstream

When a real run finds something only an upstream project can fix, we write it down with the evidence and offer it back. A person reviews every draft and files it under their own account; no agent posts upstream.

Upstream asks

Gaps, API asks and docs fixes real runs found, each with its evidence, drafted and reviewed before a person files it upstream under their own account.

Observations that disagree

When a run disagrees with a published source, avd-assess records it with the evidence, and it joins the upstream list.

Lessons from real runs

Every failure tests didn't catch becomes a lesson and a guard, in public, for anyone hitting the same thing.

Help us

Research help is as welcome as code. Each of these is a GitHub issue or a pull request in the avd-ops repos. Issues are public, so keep tenant data, names, IDs and secrets out of them.

Close a method gap

Method we wrote only because no published source covers it. Know a source that does? Tell us and the gap retires.

Send baseline evidence

Measured results from your own lab that agree or disagree with a baseline. Aggregates only, no names or IDs.

Suggest an expert to follow

Someone who publishes deep, original work on AVD. They are scored by the same method as everyone else.

Not sure where it goes?
